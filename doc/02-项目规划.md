## 1. 背景、现状与差距

`V0.1.0` 基线中的 `Database::listNotes()` 会为列表查询读取每篇笔记的 HTML 与纯文本，打开大量笔记时会产生不必要的数据搬运；最近访问的正文也不会复用。快速便签写入 `settings.quick_note`，无法在主笔记列表中统一管理。笔记标题可以直接编辑，但没有分组表、分组筛选和移动入口。

`V0.1.1` 已用 schema v2、`NoteSummary`、正文版本和 SHA-256 哈希、24 MiB 加权缓存、分组操作及正式便签记录解决这些差距；迁移只在 `user_version` 升级时运行，三字及以上搜索使用 FTS5 trigram `MATCH`。块文档、UUIDv7、手机同步、网络服务和 CRDT 不属于本任务。

## 7. 完成条件与周期清理

- 旧数据库启动后必须原位、幂等迁移，既有笔记、待办和非空快捷便签不得丢失。
- 笔记列表查询不得读取 `html` 正文；正文只在选中或缓存未命中时读取。
- 正文缓存必须用笔记内容版本校验，不得返回保存前的旧内容。
- 分组删除必须把其中笔记安全移回未分组，不得级联删除笔记。
- 快速便签保存后必须作为正式数据库笔记出现在主列表中。
- 主窗口、便签、托盘与 EXE 必须共享夜航品牌图标；可见品牌变化不得改变旧数据目录。
- 浅色菜单和组合框弹窗必须在 Windows 深色主题下显式提供深色普通/禁用文字和高对比选中状态。
- Release 构建和自动测试通过后，由开发组判断任务进入待验收或完成；没有真实 Git 提交时，不得声称已经产生关联版本。
