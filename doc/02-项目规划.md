## 1. 背景、现状与差距

`V0.1.0` 基线中的 `Database::listNotes()` 会为列表查询读取每篇笔记的 HTML 与纯文本，打开大量笔记时会产生不必要的数据搬运；最近访问的正文也不会复用。快速便签写入 `settings.quick_note`，无法在主笔记列表中统一管理。笔记标题可以直接编辑，但没有分组表、分组筛选和移动入口。

`V0.1.1` 已用 schema v2、`NoteSummary`、正文版本和 SHA-256 哈希、24 MiB 加权缓存、分组操作及正式便签记录解决这些差距；迁移只在 `user_version` 升级时运行，三字及以上搜索使用 FTS5 trigram `MATCH`。块文档、UUIDv7、手机同步、网络服务和 CRDT 不属于本任务。

`V0.1.3` 进一步用 schema v3 移除“只能有一枚活动便签”的唯一索引；主窗口不再在启动时预建隐藏便签，已置顶且上次保持打开的便签才按 ID 恢复。主窗口隐藏/最小化时清空正文缓存与当前排版文档，恢复后再按摘要版本加载。600 篇、约 21.5 MiB 样本已经进入自动性能回归；删除装饰背景位图及缩放缓存后，稳定私有内存由约 124—125 MiB 降至约 112—115 MiB，但仍高于激进的 100 MiB 目标，因此下一轮若要求显著低于 100 MiB，需要做进程/生命周期拆分或纯 Win32/DirectWrite 对照实现。

### 2.1 后续建议顺序与边界

本轮按资料安全与恢复、阅读定位与快速记录、AI 交接及语音的顺序实施。外部文档采用源码编辑／预览；航迹采用压缩快照、连续编辑合并及可保留检查点；MCP 只访问用户导出的范围并提交待确认建议；语音首版采用可选的中文 Zipformer-small-CTC INT8，完成录音／文件转写和校对插入。实时逐字显示、多语模型切换与说话人识别仍属于原规划中的后续阶段。

七项均坚持本地优先、按需加载、有限存储与低打扰。恢复与修改记录先服务单篇文档；AI 只能访问用户选择的范围；语音只在用户主动录音或选择音频时工作。手机端、云同步、全量知识图谱、白板和内置 AI 聊天不因本轮规划进入实现范围。

#### 4.1.2 后续能力边界

以下来自原七项规划的后续阶段，没有预先分配新版本或宣称实现：

## 7. 完成条件与周期清理

- 旧数据库启动后必须原位、幂等迁移，既有笔记、待办和非空快捷便签不得丢失。
- 笔记列表查询不得读取 `html` 正文；正文只在选中或缓存未命中时读取。
- 正文缓存必须用笔记内容版本校验，不得返回保存前的旧内容。
- 分组删除必须把其中笔记安全移回未分组，不得级联删除笔记。
- 每次新建桌面便签必须产生独立记录；两枚便签不得互相覆盖。保存后必须作为正式数据库笔记出现在主列表中，并可按 ID 从主列表重新打开。
- 主窗口、便签、托盘与 EXE 必须共享夜航品牌图标；可见品牌变化不得改变旧数据目录。
- 无边框主窗口必须保留菜单、最小化、最大化/还原、关闭、拖动、双击最大化和边缘缩放；便签必须保留拖动、缩放、置顶和关闭。
- 每枚便签的置顶、位置、尺寸、打开状态与 `55%—100%` 整体不透明度必须按笔记 ID 写入 `QSettings` 并在重启后恢复；不得通过降低编辑区文字自身 alpha 实现。
- 性能结论必须同时给出样本规模、统计口径与实测数值；Qt 基础内存未达目标时必须保留为已知限制。
- 浅色菜单和组合框弹窗必须在 Windows 深色主题下显式提供深色普通/禁用文字和高对比选中状态。
- 应用内备份必须先生成可独立打开且通过 `quick_check` 的数据库快照，再发布清单；保留清理不得跟随符号链接或删除不符合夜航备份命名与清单规则的目录。
- “收舟入册”必须默认保留源便签；正式笔记与有序来源关系必须在同一数据库事务中生成，正文后续被用户重排时不得丢失来源 ID 与入册时更新时间。
- 全局快捷键只接受有修饰键的单段受支持组合；新组合必须在探测注册成功后才替换旧注册，冲突失败不得写入设置，持久化文本必须与系统显示文本解耦。
- Release 构建和自动测试通过后，由开发组判断任务进入待验收或完成；没有真实 Git 提交时，不得声称已经产生关联版本。
