## 1. 市场分层

当前同类产品大致分为四类：

1. **快速记录层**：Memos、Stickies 等把“立即写下”放在组织之前。
2. **个人知识库层**：Joplin、QOwnNotes、Logseq、TriliumNext、思源强调本地资料、链接、层级或可扩展性。
3. **安全同步层**：Notesnook、Standard Notes 把端到端加密、跨端同步与备份作为核心承诺。
4. **写作/工作空间层**：Zettlr、AppFlowy 覆盖出版、数据库、项目、团队或 AI，能力宽但不是轻量桌面便签的直接替代。

夜航不宜在 `V0.1` 阶段追赶完整知识图谱、块数据库或团队协作。更合适的定位是：**Windows 上低打扰、低负载、对图片和游戏创作友好的本地灵感捕获层**。

## 3. 本轮直接吸收的结论

- **Memos 的“先写后整理”**：快捷键每次创建新便签，不要求用户先选分组。
- **Stickies 的窗口模型**：多枚窗口可同时存在，各自保存位置、透明度与置顶状态。
- **Joplin/Trilium 的一等附件与一等笔记思路**：便签继续存入 `notes` 表，而不是另建无法管理的临时文件。
- **Memos 的可见区延迟工作**：主列表只取摘要；选中后才加载正文；主窗口隐藏时清除渲染文档与正文缓存。
- **Notesnook/Stickies 的恢复意识**：自动备份与崩溃安全快照应成为下一个数据可靠性任务，而不是等同步完成后再补。
- **“先写后整理”的闭环**：`V0.1.5` 已把多枚一等便签按用户顺序汇成正式笔记，并把来源关系独立持久化；整理不再等于删除捕获原件。

## 4. 夜航的差异化候选

### 4.1 灵感航迹（优先）

用户主动触发记录时，可选择附带来源应用、窗口标题、时间、剪贴板图片和 AI 概念图生成信息；把“这张图从哪里来、对应什么提示词、当时在做哪个关卡”保存为可见元数据。该能力对游戏开发灵感比通用知识图谱更直接。

隐私边界：默认关闭来源采集，只在用户主动触发时读取；界面必须预览将保存的信息，并提供应用白名单和一键清除，不做后台键盘或屏幕监控。

### 4.2 便签入册（优先）

便签本身已经是一等笔记。`V0.1.5` 已完成“收舟入册”的正向路径：把若干便签按用户拖动顺序合并为一篇结构化笔记，保留原时间、来源 ID 和源记录，并允许指定标题与分组。待后续补充图片便签和“正文选段再次拆成桌面便签”，即可形成更完整的捕获—整理—再执行双向通路。

### 4.3 静默航行模式（优先）

建立可见的资源预算，而不只宣称“轻量”：

- 无连续轮询，自动保存、搜索和同步全部事件驱动或防抖；
- 主窗口隐藏时释放正在排版的正文、图片和正文缓存；
- 图片只在当前文章和可见尺寸内解码；
- 显示启动、便签呼出、摘要查询、私有内存与空闲 CPU 的本机基线；
- 后续允许用户选择“游戏中只保留快捷键与便签”的低负载策略。

### 4.4 灵感包（次优先）

把一篇笔记、引用图片、待办、来源航迹和 AI 提示词导出为一个可携带目录或 ZIP，内含 Markdown/HTML 清单。它比单独导出 Word 更适合把概念提交给游戏项目、版本库或另一个 AI 工具。

### 4.5 电脑私有服务器 + 手机离线发件箱（已规划、暂缓）

延续既定方向：电脑是用户自己的权威服务器；手机离线时把变更写入 outbox，检测到电脑后提交并处理冲突。该能力应在桌面数据 ID、版本、附件恢复与备份规则稳定后启动。

## 5. 建议优先级

| 优先级 | 建议 | 原因 |
| --- | --- | --- |
| P0（已落地） | 多便签、独立置顶/透明度、便签正式入库、按需正文、隐藏时释放重资源、性能回归、一致性本地备份、便签入册正向路径 | 直接强化“随时记、不中断游戏”，并闭合捕获到整理的第一段流程 |
| P1 | 灵感航迹、正文反向拆签、附件去重与孤儿恢复、备份一键恢复 | 继续形成可感知差异，也补齐数据可信度 |
| P2 | 灵感包、OCR 可搜索文本、开放只读/受控写入 API | 服务游戏创作链路且不必建设插件运行时 |
| P3 | 电脑私有服务器、手机离线 outbox、冲突界面、端到端加密 | 价值高，但必须建立在稳定数据协议之上 |
| 暂不进入 | 全量块编辑器、知识图谱、白板、团队协作、插件商店、内置 AI 聊天 | 竞品已经成熟，且会显著扩大包体、内存与维护面 |
